### 2. Sensor USB — `LIBUSB_ERROR_IO` y `LIBUSB_ERROR_ACCESS`
**Archivos:** `scripts/VALIDAR_SENSOR.bat`, `scripts/validar_sensor.py`

**Raíz del problema:**
pywws usa `device_libusb1.py` → `usb1` (python-libusb1) → requiere **WinUSB** en Zadig.
El script de diagnóstico usaba `pyusb` que sí funciona con `libusb-win32`, pero pywws necesita WinUSB.

**Estado USB al final de la sesión:**
- Driver Zadig: libusb-win32 (funciona con el diagnóstico pero NO con pywws)
- **Acción pendiente:** cambiar a WinUSB en Zadig para VID=1941 PID=8021
- El paquete `libusb1` (python-libusb1) ya está instalado en el venv — provee `libusb-1.0.dll`
- Con WinUSB + libusb1 Python package: pywws debería funcionar

**Script `validar_sensor.py` mejorado:**
- Chequea `usb1.USBContext()` (lo que pywws usa realmente) además de pyusb
- Lista TODOS los dispositivos USB detectados
- Detecta conflicto libusb-win32 vs WinUSB y avisa
- Ver: `docs/sensor_usb.md`

### 3. Dashboard — MAXTICKS y performance
**Archivos:** `src/yvy/presentation/charts/base.py`, `src/yvy/application/use_cases/query_sensor_aggregated.py`

**Bug `MAXTICKS 1606 ticks`:**
- `format_xaxis()` aplicaba `DayLocator()` sin fijar `ax.set_xlim()`.
- Matplotlib auto-escalaba el eje a un rango de ~4.4 años → intentaba generar 1606 ticks → ~1600 objetos `Text` en RAM por render.
- **Fix:** `set_xlim(now - period_delta, now)` antes del locator. Ticks: 1606 → 6-7.

### 4. Catchup recovery — `LIBUSB_ERROR_ACCESS`
**Archivos:** `src/yvy/infrastructure/pywws/live_source.py`, `src/yvy/presentation/controllers/sync_controller.py`, `scripts/launch_app.py`

**Bug:** live source y catchup intentaban abrir `WeatherStation()` simultáneamente. libusb-1.0 es exclusivo → ACCESS error.

**Fix implementado — pausa coordinada:**
- `PywwsLiveSource` tiene ahora `request_pause(timeout=120s)` / `signal_resume()` / `_check_pause()`.
- Al inicio de cada `read_live()`, se verifica si el catchup solicitó pausa.
- Si sí: se cierra `live_iter` + `WeatherStation` → USB libre → se señaliza `_paused` → se espera `_resume`.
- `SyncController.trigger_catchup()` pausa el live source antes de correr, lo reanuda en `finally`.
- `launch_app.py`: `_live_source` ahora es variable explícita, pasada al `SyncController`.

**Tiempo de espera:** el catchup espera hasta ~48s (una lectura del sensor) antes de poder correr. No se pierde la lectura actual porque se persiste antes de ceder el USB.

Ver: `docs/catchup_vs_live.md`
